# Wave Records — сайт студії звукозапису

> **Публікація на GitHub Pages (безкоштовно, без сервера):** див. [GITHUB-PAGES.md](GITHUB-PAGES.md). Нижче — повна версія з адмінкою, якій потрібен сервер.

Багатосторінковий сайт з онлайн-записом, який синхронізується з вашим Google Calendar в обидва боки, плеєром для робіт (WAV/MP3), адмін-панеллю, статистикою, Google Tag Manager, GA4 і Meta Pixel.

Сайт написаний на Node.js **без жодних сторонніх пакетів**: не потрібен `npm install`, нічого не зламається через оновлення бібліотек. База даних — один файл SQLite.

## 1. Швидкий старт

Потрібен **Node.js 22.13 або новіший** (краще 24 LTS): <https://nodejs.org>.

**Windows:** двічі клікніть `start-windows.bat`. **Mac / Linux:** `npm start` у папці проєкту.

Необов'язково: скопіюйте `.env.example` у `.env` і задайте свій `ADMIN_PASSWORD` до першого запуску.

Сайт: <http://localhost:3000>, адмінка: <http://localhost:3000/admin> (логін `admin`, пароль — з `.env`).
Якщо пароль у `.env` не задано, сайт згенерує його сам і покаже в консолі при першому запуску.

Перевірити, що все працює: `npm test` — 12 тестів бронювання та синхронізації з календарем.

## 2. Що є на сайті

| Сторінка | Що там |
|---|---|
| `/` | Перший екран, основні послуги, 4 роботи з плеєром, «Чому Wave», «Як це працює» |
| `/services` | Усі послуги в двох блоках: Sound і Media \| PR (картки в стилі liquid glass) |
| `/portfolio` | Три розділи: Vocal Mixing, Music, B2B |
| `/about` | Intro, Philosophy, Process (вертикальна лінія з червоними номерами), Atmosphere (галерея), фінальний заклик |
| `/book` | Адреса, примітка про ціну, форма: послуга → дата → час → контакти |
| `/contacts` | Асиметричний блок карток: студія, телефон, email, графік, Telegram |
| `/privacy-policy`, `/agreement` | Юридичні тексти |

**Плеєр.** Один трек грає одночасно; хвиля показує реальну форму треку (рахується автоматично при завантаженні); по хвилі можна перемотувати мишкою, пальцем або стрілками на клавіатурі. Під час відтворення внизу з'являється міні-плеєр, а смуги на першому екрані рухаються під музику. Після закінчення треку вмикається наступний зі списку.

**Бронювання.** Клієнт обирає послугу (для «Запису» — ще й тривалість), дату в календарі, вільний час і залишає контакти. Календар показує лише дні, де є вільний час. Після підтвердження клієнт бачить вікно «Запис підтверджено» з кодом і кнопкою «Додати в календар».

Захист від подвійного бронювання: кожна година сесії записується в базу окремим рядком з унікальним ключем, і перевірка + запис відбуваються в одній транзакції. Навіть якщо два клієнти натиснуть «Підтвердити» в ту саму мілісекунду, пройде лише один — другий побачить «Цей час щойно зайняли» і оновлений список вільних годин. Це перевіряється тестом з 30 одночасними заявками.

## 3. Адмін-панель

Адреса: `/admin`.

- **Огляд** — відвідувачі, перегляди, кількість бронювань, конверсія у запис, прослуховування, графік за 30 днів, найближчі сесії, джерела переходів, популярні сторінки й треки. Статистика рахується без cookies, тому працює навіть коли відвідувач не погодився на cookies.
- **Бронювання** — список з фільтрами; у картці бронювання: контакти (подзвонити / написати в Telegram), узгоджена ціна, нотатки, перенесення, скасування, «виконано». Можна додати бронювання вручну (наприклад, якщо клієнт подзвонив).
- **Треки** — завантаження WAV або MP3 у потрібний розділ, назва й артист, позначка «На головній» (до 4 треків), зміна порядку, заміна файлу, видалення.
- **Фото студії** — завантаження кількох фото одразу; кожному обираєте місце: галерея «Атмосфера», головне фото сторінки «Про студію» чи фото до етапу Record / Produce / Mix / Master / Release. Фото автоматично зменшуються і стискаються перед завантаженням. Поки фото немає, на сайті показуються графічні фрагменти у фірмових кольорах.
- **Послуги** — назви, ціни, описи, що показувати на головній, що потрапляє у форму запису і скільки триває сесія.
- **Блоки сайту** — тексти всіх блоків, включно з юридичними сторінками; будь-який блок можна приховати. Щоб додати новий блок у майбутньому, достатньо описати його у `src/content.js` — він сам з'явиться в адмінці.
- **Налаштування** — назва, домен, ID аналітики, робочі години, мінімальний час до сесії, на скільки днів наперед можна бронювати, статус Google Calendar, зміна пароля.

## 4. Google Calendar

### Як це працює

```
Сайт Wave Records ──► Система бронювання ──► Google Calendar
 (клієнт обирає        (атомарно займає        (запис, нагадування,
  послугу і час)        слот у базі, потім      ви редагуєте зі смартфона)
                        синхронізує)
        ◄──────────── зміни з календаря повертаються на сайт ◄──
```

- Нове бронювання з сайту → подія у вашому календарі (з телефоном клієнта, коментарем і посиланням на бронювання в адмінці).
- **Перенесли** подію в календарі → бронювання на сайті переноситься, старий час звільняється. Якщо новий час перетинається з іншим бронюванням, обидва залишаються, а бронювання позначається «Потребує уваги» на головній адмінки.
- **Видалили** подію в календарі → бронювання на сайті скасовується, час звільняється.
- **Скасували або перенесли** бронювання в адмінці → подія в календарі видаляється або оновлюється.
- **Будь-яка ваша інша подія** в календарі (особисті справи, «не працюю») закриває ці години для бронювання на сайті. Подія на весь день закриває весь день. Подія, позначена як «Вільний» (Free), час не закриває.
- Якщо Google тимчасово недоступний, бронювання все одно приймаються, а сайт дошле їх у календар пізніше (повтори з наростаючою паузою).
- Зміни з календаря підтягуються за push-сповіщенням від Google за кілька секунд (коли сайт працює на `https://`) і додатково щохвилини. Перед кожним бронюванням сайт ще раз звіряється з календарем.

### Підключення (≈10 хвилин, один раз)

1. Відкрийте <https://console.cloud.google.com>, створіть проєкт (наприклад, «Wave Records»).
2. **APIs & Services → Library** → знайдіть **Google Calendar API** → **Enable**.
3. **IAM & Admin → Service Accounts → Create service account**. Назва довільна, ролі не потрібні.
4. Відкрийте створений акаунт → **Keys → Add key → Create new key → JSON**. Завантажиться файл — покладіть його в папку сайту як `google-service-account.json`. **Нікому не пересилайте цей файл.**
5. Скопіюйте email сервісного акаунта (вигляду `wave@ваш-проєкт.iam.gserviceaccount.com`).
6. Відкрийте Google Calendar у браузері → ⚙️ **Налаштування** → зліва ваш календар → **Поділитися з певними людьми** → **Додати людей** → вставте email сервісного акаунта → дозвіл **«Вносити зміни в події»**.
7. Там само, у розділі **Інтеграція календаря**, скопіюйте **Ідентифікатор календаря** (для основного календаря — це ваша Gmail-адреса).
8. У файлі `.env`:
   ```
   GOOGLE_SERVICE_ACCOUNT_FILE=./google-service-account.json
   GOOGLE_CALENDAR_ID=ваша.адреса@gmail.com
   PUBLIC_URL=https://ваш-домен.ua
   ```
9. Перезапустіть сайт → адмінка → **Налаштування** → **Перевірити й синхронізувати зараз**. Має з'явитися «Синхронізовано з календарем …».

Порада: можна створити окремий календар «Wave — студія» і поділитися лише ним; тоді особисті події не блокуватимуть студію. Якщо ж хочете, щоб особисті справи теж закривали час — використовуйте основний календар.

## 5. Аналітика

Адмінка → **Налаштування** → вставте ID:

- **Google Tag Manager** (`GTM-XXXXXXX`) — рекомендований спосіб: GA4, Meta Pixel та інші теги налаштовуються всередині GTM.
- **Google Analytics 4** (`G-XXXXXXXXXX`) — лише якщо GA4 *не* підключено через GTM (інакше перегляди рахуватимуться двічі).
- **Meta Pixel** (лише цифри).

Сайт показує банер згоди на cookies і працює з **Google Consent Mode v2**: до згоди Google-теги не ставлять рекламних і аналітичних cookies, а Meta Pixel узагалі не завантажується.

Події, які сайт надсилає в `dataLayer` (для тригерів у GTM):

| Подія | Коли | Параметри |
|---|---|---|
| `booking_start` | клієнт обрав послугу у формі | `service` |
| `booking_confirmed` | запис успішно створено (у Pixel — `Schedule`) | `service`, `booking_code` |
| `audio_play` | перше відтворення треку | `track_title` |
| `cta_click` | натискання основних кнопок | `cta` |
| `consent_update` | відвідувач обрав налаштування cookies | `consent` |

Для реклами в Meta як конверсію використовуйте подію `Schedule`, у Google Ads — `booking_confirmed`.

## 6. Telegram-сповіщення

Необов'язково, але зручно: про кожне нове бронювання прийде повідомлення.

1. У Telegram напишіть [@BotFather](https://t.me/BotFather) → `/newbot` → отримаєте токен.
2. Напишіть своєму боту будь-яке повідомлення, потім відкрийте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайдіть `"chat":{"id":…}`.
3. У `.env`: `TELEGRAM_BOT_TOKEN=…` і `TELEGRAM_CHAT_ID=…`, перезапустіть сайт.

## 7. Розміщення в інтернеті

Сайту потрібен сервер з Node.js і постійним диском (для бази та завантажених треків). Звичайний «хостинг для HTML» або Vercel/Netlify не підійдуть. Найпростіше — невеликий VPS (Hetzner, DigitalOcean, українські VPS-провайдери) за 4–6 $/міс.

### Варіант А: VPS + Caddy (автоматичний HTTPS)

```bash
# на сервері (Ubuntu)
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash - && sudo apt install -y nodejs caddy
sudo mkdir -p /opt/wave && sudo chown $USER /opt/wave
# скопіюйте папку проєкту в /opt/wave, створіть там .env (NODE_ENV=production, TRUST_PROXY=1, PUBLIC_URL=https://…)
```

`/etc/caddy/Caddyfile`:
```
waverecords.ua, www.waverecords.ua {
    request_body {
        max_size 450MB
    }
    reverse_proxy 127.0.0.1:3000
}
```

Автозапуск — `/etc/systemd/system/wave.service`:
```ini
[Unit]
Description=Wave Records
After=network.target

[Service]
WorkingDirectory=/opt/wave
ExecStart=/usr/bin/node --disable-warning=ExperimentalWarning server.js
Restart=always
User=www-data
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

```bash
sudo chown -R www-data /opt/wave/data
sudo systemctl enable --now wave && sudo systemctl reload caddy
```

Якщо використовуєте nginx замість Caddy, додайте `client_max_body_size 450m;` — інакше великі WAV не завантажаться.

### Варіант Б: Docker

```bash
docker compose up -d --build
```

Дані зберігаються в папці `./data` поруч із проєктом.

## 8. Резервні копії

Усе важливе лежить у папці `data/`: база `wave.db` і завантажені треки та фото в `uploads/`. Достатньо регулярно копіювати цю папку. Для копії «на ходу», без зупинки сайту:

```bash
sqlite3 data/wave.db ".backup data/backup-$(date +%F).db"
```

## 9. Перед запуском — перевірте

- **Контакти**: телефон `+380 XX XXX XX XX` і Telegram `@nick_name` — це заглушки з ТЗ. Змініть в адмінці → Блоки сайту → Контакти.
- **Ціна «Пісні під ключ»**: на головній за ТЗ стоїть «14 000 грн», на сторінці послуг — «від 20 000 грн». Виправте одну з них: адмінка → Послуги → «Пісня під ключ» → «Ціна на головній».
- **«Дистрибуція» (500 грн)** є на головній, але не на сторінці послуг і не у формі запису — так у ТЗ. Якщо треба — увімкніть відповідні галочки в адмінці → Послуги.
- **Юридичні тексти** взяті з ТЗ; назву «feat.» і домен feat.com.ua замінено на ваші (підставляються з Налаштувань). Договір оферти написаний для інтернет-магазину товарів (доставка, повернення товару, ПДВ) і не відповідає послугам студії — варто переписати під послуги або показати юристу.
- **Тривалість сесій** для кожної послуги (Зведення — 2 год, Мастеринг — 1 год, Wave Pro — весь день тощо) — це моє припущення, змініть за потреби в адмінці → Послуги → «Головна та бронювання».
- **Шрифт Archivo Black не має кириличних літер.** Тому латиниця (WAVE RECORDS, RECORD, MIX…) набрана Archivo Black, а українські заголовки — щільним Inter Tight Black, найближчим за характером. Обидва підключаються з Google Fonts.

## 10. Структура проєкту

```
server.js              запуск сервера
start-windows.bat      запуск подвійним кліком на Windows
static/build.js        збірка версії для GitHub Pages
content/, media/       тексти, ціни, треки й фото для версії GitHub Pages
.github/workflows/     автопублікація на GitHub Pages
src/
  app.js               маршрути, обробка помилок, заголовки безпеки
  config.js            налаштування з .env
  db.js                схема бази SQLite і початкові послуги
  booking.js           доступність, атомарне резервування, скасування, перенесення
  gcal.js              двостороння синхронізація з Google Calendar
  content.js           опис редагованих блоків сайту та їхні тексти
  legal.js             тексти політики конфіденційності та договору
  settings.js          робочі години, ID аналітики
  stats.js             власна статистика без cookies
  auth.js              вхід в адмінку, сесії, захист від CSRF
  uploads.js           приймання файлів WAV/MP3/фото
  notify.js            Telegram-сповіщення
  routes/site.js       сторінки сайту та API бронювання
  routes/admin.js      адмін-панель
  views/               HTML-шаблони сторінок
public/
  css/site.css         стилі сайту (кольори, liquid glass, адаптивність)
  js/site.js           меню, плеєр, візуалізатор, банер cookies
  js/book.js           форма бронювання
  css/admin.css, js/admin.js
test/booking.test.js   тести бронювання й синхронізації
data/                  база й завантажені файли (створюється автоматично)
```
