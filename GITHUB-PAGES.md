# Запуск сайту Wave Records на GitHub Pages

GitHub Pages безкоштовно публікує сайт з вашого репозиторію. Сайт збирається сам: щойно ви змінюєте ціну, додаєте трек чи фото на GitHub, за 1–2 хвилини сайт оновлюється.

**Чим ця версія відрізняється від повної:**
- Запис працює через сторінку бронювання Google Calendar, вбудовану на `/book`. Google сам показує вільний час з вашого календаря, не допускає подвійних записів і надсилає клієнту підтвердження.
- Адмінки немає. Треки, фото, ціни й тексти змінюються файлами в репозиторії (усе можна робити в браузері).
- Статистика — через Google Analytics / Meta Pixel.

Безкоштовно GitHub Pages працює лише з **публічним** репозиторієм: код сайту бачитимуть усі. Секретів у ньому немає, тож це безпечно.

---

## Крок 1. Покладіть нові файли в папку сайту

1. Розпакуйте архів `wave-records.zip`.
2. Відкрийте розпаковану папку `wave-records`, виділіть усе всередині (Ctrl+A) і скопіюйте (Ctrl+C).
3. Відкрийте вашу папку `C:\Users\Юра\Desktop\wave-records` і вставте (Ctrl+V). На питання Windows оберіть **«Замінити файли в місці призначення»**.

Якщо такої папки ще немає — просто покладіть розпаковану папку на робочий стіл.

## Крок 2. Опублікуйте репозиторій на GitHub (публічним)

У **GitHub Desktop**:

**Якщо репозиторій ще не створено:**
1. **File → Add local repository…** → оберіть `C:\Users\Юра\Desktop\wave-records`.
2. Натисніть **create a repository** → **Create repository** (поле Git ignore залиште None).
3. Ліворуч перевірте список файлів: там **не повинно бути** папки `data` чи файлу `.env`.
4. Унизу в **Summary** напишіть `Сайт для GitHub Pages` → **Commit to main**.
5. **Publish repository** → **зніміть** галочку **Keep this code private** → **Publish repository**.

**Якщо репозиторій уже опубліковано (приватним):**
1. У GitHub Desktop з'являться змінені файли. Напишіть `Сайт для GitHub Pages` → **Commit to main** → **Push origin**.
2. На github.com відкрийте репозиторій → **Settings** → **General** → у самому низу **Danger Zone** → **Change visibility** → **Change to public** → підтвердіть.

## Крок 3. Увімкніть GitHub Pages

1. На github.com відкрийте репозиторій `wave-records`.
2. **Settings** → ліворуч **Pages**.
3. У розділі **Build and deployment** → **Source** оберіть **GitHub Actions**.

## Крок 4. Запустіть публікацію

1. Вкладка **Actions** угорі репозиторію.
2. Ліворуч **Публікація сайту** → праворуч **Run workflow** → зелена кнопка **Run workflow**.
3. Зачекайте 1–2 хвилини, поки біля запуску з'явиться зелена галочка ✅.
4. Адреса сайту — у **Settings → Pages** («Your site is live at …»). Зазвичай це `https://ЛОГІН.github.io/wave-records/`.

Якщо раніше вже був червоний ❌ запуск (він міг статися до кроку 3) — це нормально, просто запустіть ще раз.

## Крок 5. Підключіть онлайн-запис (Google Calendar)

1. На комп'ютері відкрийте <https://calendar.google.com>.
2. Натисніть **Створити** (**Create**) → **Розклад зустрічей** (**Appointment schedule**).
3. Заповніть:
   - **Назва:** `Сесія у Wave Records`
   - **Тривалість:** наприклад, 1 година
   - **Доступність:** Пн–Пт, 10:00–20:00 (або ваш графік)
   - У налаштуваннях форми бронювання, якщо є така можливість, додайте поле для телефону.
4. **Зберегти** (**Save**).
5. Відкрийте створений розклад → **Поділитися** (**Share**) → **Вбудувати на вебсайт** (**Website embed**) → **Вбудований календар** (**Inline calendar**) → **Копіювати** (**Copy**).
6. На github.com відкрийте файл `content/booking-link.txt` → олівець ✏️ (**Edit this file**) → вставте скопійований код → **Commit changes…** → **Commit changes**.
7. За 1–2 хвилини на сторінці «Запис» з'явиться календар.

Можна вставити і звичайне посилання на сторінку запису. Тоді на сайті буде кнопка «Обрати дату й час», яка відкриває запис у новій вкладці.

Безкоштовний акаунт Google дає одну сторінку запису: у ній одна тривалість для всіх послуг. Клієнт вказує послугу в коментарі, а деталі й ціну ви узгоджуєте після запису (про це вже написано на сторінці).

## Крок 6. Додайте треки

Папки:

| Папка | Розділ сайту |
|---|---|
| `media/audio/vocal` | Vocal Mixing (перші 4 треки показуються на головній) |
| `media/audio/music` | Music — біти й аранжування |
| `media/audio/b2b` | B2B продакшн для бізнесів |

**Як назвати файл:** `01 - Артист - Назва треку.mp3`
- Число на початку задає порядок і на сайті не показується.
- Усе до другого ` - ` — артист, далі — назва. Для бітів можна просто `Beat 1.mp3`.

**Як завантажити через браузер (файли до 25 МБ):**
1. Відкрийте потрібну папку на github.com (наприклад, `media` → `audio` → `vocal`).
2. **Add file** → **Upload files** → перетягніть файли → **Commit changes**.

**Файли 25–100 МБ:** покладіть їх у ту саму папку на комп'ютері (`wave-records\media\audio\vocal`), потім у GitHub Desktop **Commit to main** → **Push origin**.

Порада: для сайту краще MP3 320 kbps (~8–10 МБ на трек). WAV у 5–10 разів важчий і довго вантажиться на телефоні. Тривалість і форма хвилі розраховуються автоматично.

**Видалити трек:** відкрийте файл на github.com → **⋯** (три крапки) → **Delete file** → **Commit changes**.
**Перейменувати або змінити порядок:** перейменуйте файл у папці на комп'ютері → GitHub Desktop → Commit → Push.

## Крок 7. Додайте фото студії

| Папка | Де на сайті |
|---|---|
| `media/photos/gallery` | Галерея «Атмосфера студії» (4–6 фото) |
| `media/photos/about` | Головне фото сторінки «Про студію» (1 фото) |
| `media/photos/record` … `release` | Фото до етапів Record, Produce, Mix, Master, Release (по 1 фото) |

- Назва файлу стає описом фото для пошуковиків, наприклад `Вокальна кабіна.jpg`.
- Формат JPG, PNG або WEBP, бажано до 2–3 МБ і ~2000 px по довшій стороні.
- Завантажуються так само: **Add file → Upload files**.

Поки фото немає, на сайті показуються графічні фрагменти у фірмових кольорах.

## Крок 8. Змінюйте тексти, ціни й контакти

Усе лежить у папці `content`:

| Файл | Що в ньому |
|---|---|
| `contacts.json` | Телефон, email, Telegram, адреса, графік |
| `services.json` | Послуги й ціни: `home` — картки на головній, `sound` і `media` — сторінка «Послуги» |
| `texts.json` | Усі тексти сторінок. `"visible": false` приховує блок |
| `settings.json` | Назва, домен, ID Google Tag Manager, Google Analytics, Meta Pixel |
| `privacy-policy.md`, `agreement.md` | Юридичні сторінки (`## Заголовок`, `- пункт`, `**жирний**`) |
| `booking-link.txt` | Код або посилання на запис Google Calendar |

**Як редагувати:** відкрийте файл → олівець ✏️ → змініть → **Commit changes**.

**Правила для файлів `.json`:**
- Змінюйте лише текст **усередині лапок**: `"phone": "+380 67 123 45 67"`.
- Не видаляйте лапки, коми, дужки `{ } [ ]`.
- Якщо потрібні лапки в тексті — пишіть «ялинки».
- Щоб додати послугу, скопіюйте рядок з іншою послугою разом із комою в кінці.

**Якщо помилились:** сайт не зламається, просто залишиться попередня версія, а у вкладці **Actions** з'явиться червоний ❌. Відкрийте його → **Збірка** → там написано, в якому файлі й рядку помилка. Виправте файл, і сайт оновиться.

## Крок 9. Власний домен (наприклад, waverecords.ua)

1. GitHub: **Settings → Pages → Custom domain** → введіть `waverecords.ua` → **Save**.
2. У панелі реєстратора домену додайте DNS-записи:

   | Тип | Ім'я | Значення |
   |---|---|---|
   | A | @ | 185.199.108.153 |
   | A | @ | 185.199.109.153 |
   | A | @ | 185.199.110.153 |
   | A | @ | 185.199.111.153 |
   | CNAME | www | `ЛОГІН.github.io` |

3. Зачекайте (до 24 годин), поки GitHub покаже, що домен працює, і поставте галочку **Enforce HTTPS**.
4. **Обов'язково** перезапустіть публікацію: **Actions → Публікація сайту → Run workflow**. Сайт перезбереться під нову адресу.
5. У `content/settings.json` впишіть домен у поле `"domain"`.

---

Повна версія сайту з адмінкою та власною системою бронювання нікуди не ділася: вона в тій самій папці й запускається як раніше (`npm start`, див. README). Якщо згодом вирішите перейти на сервер (Render тощо), репозиторій підійде без змін.
